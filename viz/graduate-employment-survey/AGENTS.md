# AGENTS.md

The computing salary premium widened: Graduate Employment Survey degrees' gross monthly medians relative to each year's median: computing-titled degrees moved from 0.6% below it in 2013 to 36.4% above it in 2024.

Live: https://teoyujie.org/visuals/graduate-employment-survey/

## Source of truth

The standalone repository [yujieteo/graduate-employment-survey](https://github.com/yujieteo/graduate-employment-survey) is where this visualisation and its tests develop and where CI runs them. `viz/graduate-employment-survey/` in [yujieteo/visuals](https://github.com/yujieteo/visuals) is a byte-for-byte port of its page files, with its data files in `data/graduate-employment-survey/`. yujieteo/site publishes it at <https://teoyujie.org/visuals/graduate-employment-survey/> from the yujieteo/visuals commit pinned in its `data/visuals/graduate-employment-survey.pin`. Neither runs this repository's tests.

## Files

| File | Role |
| --- | --- |
| `index.html` | Generated page. Do not hand-edit. |

## Build, test and verify

Run from the root of a yujieteo/graduate-employment-survey checkout (Node 22; the tests need nothing installed, the type check needs `npm ci`):

```sh
npm ci && npm run typecheck
node --test 'tests/*.test.mjs'
```

`npm run typecheck` checks the JSDoc types in `report.js` and the tests with TypeScript's `tsc` (`tsconfig.json`; no emit, no compile step). After changing `report.js`, regenerate the page in yujieteo/visuals, which inlines it.

`index.html` is generated by `scripts/build_ges.py` in yujieteo/visuals, whose paths assume that repository's layout (`viz/graduate-employment-survey/` for the page files, `data/graduate-employment-survey/` for the data files); regenerate it there (`--verify` checks the committed page) and copy the result back here. Never hand-edit `index.html`. CI (`.github/workflows/ci.yml`) runs the suite on every push and pull request.

## Change workflow

1. Change and test here. Run the suite and check the page end to end: open `index.html` in a browser, use each control and both deck buttons, and confirm the console shows no errors. When a change adds or removes tests, time the suite before and after (`time node --test 'tests/*.test.mjs'`) and give both times in the pull request. Validate the branch with no-mistakes and get CI green.
2. Port to yujieteo/visuals: copy `index.html`, `beamdswitch.js`, `report.js`, `AGENTS.md`, `SKILLS.md` and `LICENSE` byte for byte into `viz/graduate-employment-survey/` and `raw.csv` and `meta.json` into `data/graduate-employment-survey/`. `README.md`, `tests/`, `.github/`, `.gitignore` and the type-check tooling (`package.json`, `package-lock.json`, `tsconfig.json`) stay here.
3. Publish: a yujieteo/site pull request moves `data/visuals/graduate-employment-survey.pin` to the new yujieteo/visuals commit. It runs only the site-level tests, never this repository's.

## Data and tests

- Data: `raw.csv` and `meta.json`.
- Deck report: `report.js` in this folder.
- Tests: `tests/graduate-employment-survey-beamdswitch.test.mjs`, and `tests/voice-beamdswitch.test.mjs` for the deck's narration voice.

## Conventions

- Single self-contained HTML page: CSS, data and JavaScript are inline, with no external requests.
- Tests run with `node --test` (JavaScript) or `unittest` (Python) only; never add Vitest, pytest or another runner. `package.json` exists only to pin the type-check tooling (TypeScript and Node's types) and holds no runtime dependencies.
- `beamdswitch.js` stays byte-identical to yujieteo/site `templates/beamdswitch.js`; the tests check it.
- Exported beamdswitch decks declare `voice: bf_emma` (the default in `beamdswitch.js`).
- WebMCP tools are read-only (`annotations: {readOnlyHint: true}`) and the page works without `modelContext`.
- Never commit credentials, host details or absolute home-directory paths.
