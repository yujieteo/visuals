## Data and the monthly refresh

`raw.json` is one snapshot. The pipeline in `pipeline/` makes it from public sources only, with no account and no paid API. The work directory is `build/te-work/` (outside Git). Set `TE_WORK` to use a different folder.

| Command | Result |
| --- | --- |
| `python3 pipeline/run.py` | Resolves the newest source versions, fetches them, extracts mathlib, runs the stages, reuses the judge answers, assembles and publishes |
| `python3 pipeline/run.py --offline` | The same steps from the work directory, with no network |
| `python3 pipeline/run.py --from judge` | Continues after the judge writes the answers listed in `<work>/judge/todo.json` |
| `python3 pipeline/fullbuild.py` | Writes the full-corpus page with every mathlib theorem to `<work>/full/theorem-explorer/index.html` |

Obey these rules:

1. Run the refresh by hand. Do not schedule it. The viewer never refreshes.
2. If a step fails, the run stops before `publish`. Thus the committed snapshot stays.
3. If the judge must assess new or changed results, the run stops with exit code 3. Write the answers, then run `--from judge`.
4. Read `<work>/refresh/report.json` for the steps, failures, omissions and change counts.
5. Read `<work>/out/change-report.json` for the source, measurement, judge, rubric and identity changes.
6. Find the old snapshots in `<work>/snapshots/<id>/raw.json`.

The source pins are in `data/sources/pins.json`. The Lean extractor is in `pipeline/lean/`. It needs a Lean toolchain in `<work>/elan`.
