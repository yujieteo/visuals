Universal Data Workbench

Import CSV or Parquet tables and see what each column holds: its type, its role, what is missing, what does not read and what is unusual. You need no question and no chart to start.

A preview: step 1 of 7, import and inspect

This version imports and inspects tables. The steps still to come, each in a later version of this page:

  1. Charts and candidates. Every valid chart of a documented grammar for each table, each accounted for as valid, excluded, failed or incomplete, with field, label, scale and layout edits.
  2. Statistics and ranking. Two lists, unusual patterns and statistically supported patterns, with a test catalogue, Benjamini–Yekutieli adjusted p-values and six distinct highlights per list.
  3. Publication figures. SVG, PDF and PNG at set sizes in millimetres, with general, Nature and Science presets and a check of each figure at its final size.
  4. Export package and beamdswitch. One download with every valid figure, the report, the specifications, the statistics, a reproducibility manifest and a beamdswitch deck; projects save and reopen.
  5. SQL and table algebra. A SQL editor and visual controls for joins, grouping, windows, pivot and unpivot, each recorded as a reproducible transformation.
  6. Phones, speed and acceptance. Full-workflow tests on phones, a 1 million row benchmark, measured phone limits with a Measure this device button, and the acceptance checks.

      How the workbench reads a table

      • A CSV is imported as text: every value stays exactly as written. The workbench reads a column as a type only for analysis, so the table never changes.
      • A column reads as a type when at least 95% of the values present fit it: yes or no, whole number, decimal, ISO date, ISO date-time, time, or one other date layout. Otherwise it is categorical (at most 1,000 levels and fewer than half distinct) or text. The share is shown as the uncertainty.
      • Empty values are missing. Markers such as NA, N/A or null are counted apart and become missing only when you approve it. So do stand-ins such as -999.
      • Dates whose day and month order is ambiguous, or that mix two layouts, stay text until you choose a layout.
      • An identifier is never a measure: a name such as id, code or zip, leading zeros, UUIDs, or nearly unique values that run without gaps make one.
      • Unusual values have a robust z above 3.5, where z = (x − median) / (1.4826 × the median absolute deviation). They stay in the data, apart from suspected errors.
      • Every result uses all rows of the table. A table imported as a seeded sample says so everywhere.

      Engine: DuckDB v1.5.4 through DuckDB-WASM 1.33.1-dev57.0, one thread, with no extension except Parquet and no access outside the files you give it.
