# AGENTS.md

Marvell cash conversion: Marvell's (MRVL) annual revenue and operating cash-flow margin from audited SEC filings, as a bar chart with a Revenue / Operating cash margin toggle.

Live: https://teoyujie.org/visuals/marvell/

## Source of truth

The standalone repository [yujieteo/marvell](https://github.com/yujieteo/marvell) is where this visualisation and its tests develop and where CI runs them. `viz/marvell/` in [yujieteo/visuals](https://github.com/yujieteo/visuals) is a byte-for-byte port of its page files, with its data files in `data/marvell/`. yujieteo/site publishes it at <https://teoyujie.org/visuals/marvell/> from the yujieteo/visuals commit pinned in its `data/visuals/marvell.pin`. Neither runs this repository's tests.

## Files

| File | Role |
| --- | --- |
| `index.html` | Generated page. Do not hand-edit. |
| `beamdswitch.js` | Unchanged copy of the site's beamdswitch report template, inlined by the builder. |
| `AGENTS.md`, `SKILLS.md`, `LICENSE` | Agent guides and the MIT licence. |

## Build, test and verify

Run from the root of a yujieteo/marvell checkout (Node 22; nothing to install):

```sh
node --test 'tests/*.test.mjs'
```

`index.html` is generated by `scripts/build_stock_cases.py` in yujieteo/visuals, whose paths assume that repository's layout (`viz/marvell/` for the page files, `data/marvell/` for the data files); regenerate it there (`--verify` checks the committed page) and copy the result back here. Never hand-edit `index.html`. CI (`.github/workflows/ci.yml`) runs the suite on every push and pull request.

## Change workflow

1. Change and test here. Run the suite and check the page end to end: open `index.html` in a browser, use each control and both deck buttons, and confirm the console shows no errors. When a change adds or removes tests, time the suite before and after (`time node --test 'tests/*.test.mjs'`) and give both times in the pull request. Validate the branch with no-mistakes and get CI green.
2. Port to yujieteo/visuals: copy `index.html`, `beamdswitch.js`, `AGENTS.md`, `SKILLS.md` and `LICENSE` byte for byte into `viz/marvell/` and `raw.json` and `meta.json` into `data/marvell/`. `README.md`, `tests/` and `.github/` stay here. `scripts/templates/stock-cases-report.js` is not ported: it is a copy of that builder's own `scripts/templates/stock-cases-report.js`, shared with the airbnb, arm, marvell and panw pages, so change it there first.
3. Publish: a yujieteo/site pull request moves `data/visuals/marvell.pin` to the new yujieteo/visuals commit. It runs only the site-level tests, never this repository's.

## Data and tests

- Data: `raw.json` (SEC XBRL company facts) and `meta.json`.
- Deck report: `scripts/templates/stock-cases-report.js`, a copy of the builder's template (the builder inlines it; there is no `report.js` at the root).
- Tests: `tests/stock-cases-beamdswitch.test.mjs`, `tests/stock-cases-tools.test.mjs` for the WebMCP tools, and `tests/voice-beamdswitch.test.mjs` for the deck's narration voice.

## Conventions

- Single self-contained HTML page: CSS, data and JavaScript are inline, with no external requests.
- Tests run with `node --test` (JavaScript) or `unittest` (Python) only; never add Vitest, pytest or another runner.
- `beamdswitch.js` stays byte-identical to yujieteo/site `templates/beamdswitch.js`; the tests check it.
- Exported beamdswitch decks declare `voice: bf_emma` (the default in `beamdswitch.js`).
- WebMCP tools are read-only (`annotations: {readOnlyHint: true}`) and the page works without `modelContext`.
- Never commit credentials, host details or absolute home-directory paths.
