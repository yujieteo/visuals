# AGENTS.md: Generating Functions Lab

Generating functions taught as a calculus for discrete structures: 34 levels from encoding and the geometric series to roots-of-unity filters, the DFT as evaluation at roots of unity, the inverse DFT as coefficient extraction, partitions and singularity analysis, with every coefficient checked against an independent count. Live at <https://teoyujie.org/visuals/generating-functions/>; its data is published at <https://teoyujie.org/visuals/generating-functions/data.json>.

## Source of truth

The standalone repository [yujieteo/generating-functions](https://github.com/yujieteo/generating-functions) is where this visualisation and its tests develop and where CI runs them; it is the source of truth. `visuals/generating-functions/` in [yujieteo/site](https://github.com/yujieteo/site/tree/main/visuals/generating-functions) is a port of its page files, refreshed when the visualisation is updated, and the site runs no logic tests for it. Porting copies the folder minus `tests/` and `.github/`. AGENTS.md and SKILLS.md therefore must not link into either (the site checks that their links resolve).

## Files and data

See [README.md](README.md). `index.html` is generated by `build.py` from `template.html`, `raw.json`, `engine.js`, `lessons.js`, `beamdswitch.js` and `ui.js`; never edit it by hand. `engine.js` is the exact mathematical core (`self.GF`, or `require`; no DOM), `lessons.js` the curriculum, problem ladder, verification engine and beamdswitch reports (`self.GFLab`), and `ui.js` the page and its WebMCP tools. `raw.json` (published as `data.json`) is generated from the lessons by `raw.mjs`.

The tests are in `tests/`, with read-only copies of beamdswitch's deck parsers and the site's shared template (`templates/beamdswitch.js` and `templates/beamdswitch-report.md`) in `tests/fixtures/beamdswitch/`.

## Build, test and verify

From the repository root:

```sh
node raw.mjs > raw.json   # after changing lessons.js
python3 build.py          # after changing any source
node --test 'tests/*.test.{mjs,cjs}'
python3 -m unittest discover -s tests -p 'test_*.py'
```

CI (`.github/workflows/ci.yml`) runs both test commands on every push and pull request: `tests/generating-functions.test.mjs` (the mathematics against independent enumerations, raw.json, deep links, search, TeX), `tests/generating-functions-beamdswitch.test.mjs` (every lesson, problem and the full deck parsed with beamdswitch's own parser), `tests/generating-functions-page.test.mjs` (every route boots against a stand-in DOM, the WebMCP tools, no-network and no-JavaScript checks) and `tests/test_generating_functions.py` (build reproducibility and the self-test under Node). In yujieteo/site the only checks for the lab are the site's integration tests: the published copy, the catalogue stub and the folder docs. The page also runs its self-test from the `run_self_tests` tool. When the site's `templates/beamdswitch.js` changes, copy it to both `beamdswitch.js` and `tests/fixtures/beamdswitch/template.js`, then rebuild.

## Conventions

- `index.html` is one self-contained HTML file: no network requests, no external scripts, fonts or TeX library. It works offline.
- Counting is exact (BigInt integers, rationals, and ℤ[ζ_N] for values at roots of unity); floating point is only for pictures and asymptotics, with stated tolerances.
- OGF A(x) = Σ aₙxⁿ; EGF Σ aₙxⁿ/n!; Fibonacci F₀ = 0; the DFT uses ω = e^{+2πi/N}, so numpy's `fft` entry k is entry N − k here.
- Tests use Node's built-in `node --test` runner and Python `unittest` only; never add Vitest, Jest or a `package.json`.
- The beamdswitch decks are written with the unchanged shared template (`beamdswitch.js`, a copy of yujieteo/site's `templates/beamdswitch.js`) and declare `voice: bf_emma` in their front matter.
- WebMCP tools stay read-only (`readOnlyHint: true`), never change the page, and keep their names equal to `webmcp_tools` in `data/visuals/generating-functions.yaml` in yujieteo/site.
